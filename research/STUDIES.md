# Bounded studies and negative results

These are research outcomes, **not additional successful production patches**. The full local experiment archives contain more logs than this concise public index; missing raw data or code are not implied to have been independently reproduced here.

| Study | Observation | Decision |
|---|---|---|
| Early vectorized Hash Join C0.5–C3 | Function-level hotspots and a narrow C2.2 Gather-elision win; compact pointer index, dense layout and forced dictionary emission lost on controlled cases. Manual pre-aggregation wins came from a changed whole-query plan, not a new join kernel. | Keep [C2.2 patch](hash-join-rhs-elision/rhs_output_none.patch); no general join-layout claim. |
| Compact aggregation Spill Modes 8–14 | Under shared 2 GiB hard RAM + 2 GiB temp, four concurrent 32M-row COUNT/SUM queries: native completed **8/20, 3/20**; Mode 9 **20/20, 20/20**. At 1 GiB hard RAM Mode 9 had an OOM kill per class; no-spill conversions and extra allocations remained. | Conditional disk-quota success, **No-Merge**. No safe native compact-spill format or bounded-memory implementation was completed. [Final verdict](compact-spill/FINAL_VERDICT.md). |
| TupleData / cross-operator allocation | Post-fix sampled Build shares were about 4.41% of aggregation, 1.64% of join and 0.54% of ordinary sort query CPU; the shared structure was not a shared dominant bottleneck. | No general TupleData optimization. [Post-fix gate](studies/tupledata.md); separate #27733 bug-fix candidate is in the main README. |
| Top-N late materialization | Large-text positive cases existed, but a compressed-string control slowed **2.40→2.79 ms**; cheap logical width did not predict physical savings. | No new C++ patch or robust admission policy. [Final gate](studies/topn-late-materialization.md). |
| FastLanes learned/budgeted encoding selection | Early samples misranked candidates; decision margins overlapped; 7-vector trial was not an all-vector oracle. The short-sample rule has a [correctness qualification](fastlanes-sample-gate/ERRATUM.md). | Characterization, not a reliable learned selector or completed thesis mechanism. [Cross-source result](fastlanes-sample-gate/BUDGET_TRACE.md). |
| DuckLake workload-driven layout | On 630k real records, many layout-query gaps were below 1 ms; fixed sorting was a strong baseline, and maintenance cost was not repaid. Eightfold duplication was not a second real source. | Dynamic reclustering No-Go; no patch. [Gate](studies/ducklake-layout.md). |
| DuckLake vector retrieval / snapshot prototype (C13) | PDX + DuckLake end-to-end small-payload p50 was about **5.54/6.34 ms** on SIFT/GloVe; PDX search itself <1 ms. Single-SQL and file-aware controls did not remove the materialization cost. External base+delta snapshots worked in controlled updates but did not beat full rebuild on query latency. | Feasible prototype, no independently validated new retrieval mechanism or production extension. [Feasibility](studies/ducklake-vector-feasibility.md), [SQL cost](studies/ducklake-vector-sql-cost.md), [snapshot](studies/ducklake-vector-snapshot.md). |
| Vector similarity join / BatchTopK (C15) | SIFT1M crossover: for 64 queries PDX 18.08 ms vs GEMM 75.06 ms; for 4096, PDX 1180.41 ms vs GEMM 615.67 ms, with higher GEMM RSS. Existing PDX/Faiss/batch-search work overlaps the core idea. | Useful pilot, not a completed memory-bounded engine or novel join thesis. [C15 verdict](studies/vector-join.md), [BatchTopK gate](studies/batchtopk.md). |
| CSV autodetection robustness (C18) | Six publicly sourced files showed confirmed silent row loss; other row-count mismatches were not automatically bugs, and existing warning/issue fixes covered parts of the space. | Triage result, no independent C++ patch or broad thesis mechanism. [Gate](studies/csv-autodetection.md). |
| Stretto similarity-join memory | Candidate materialization RSS rose from 93.8 to 514.1 MB from 0.1M to 4M candidates; chunking one backend does not bound the whole operator. | Separate from the cache/replay patch; no join-engine claim. [Gate](studies/stretto-similarity-join-memory.md). |
| Resource-aware optimizer diagnostics | Reproduced resource-sensitive plan behavior and built a recorder; a simple memory-budget sweep plus EXPLAIN/Profile explained as much as the new diagnostic. | Useful tooling, no optimizer patch or thesis-level selector. [Held-out gate](studies/optimizer-diagnostics.md). |
| Interactive OLAP query-family sharing | Public dashboard workloads contained real repeat work, but static always-materialize won six of seven natural states; one state slowed by 5.9%, and materialization increased RSS. | Sharing opportunity confirmed, new dynamic admission mechanism No-Go. [Real-workload gate](studies/olap-query-family.md). |

Ideas without an independently verifiable final implementation (for example a multi-column representation proposal or disk-resident IVF proposal) are **not** counted as experiments or successful patches.
